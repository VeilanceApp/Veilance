Indicator file format and matching guide

A file may contain one indicator, an array, or an object with an indicators array. The easiest rule matches a built-in source with indicatorId. For a narrower rule, copy the exact API and action shown in Complete visit details. Keep the matching built-in indicator enabled so its signals are available.

{
  "id": "repeated-font-probing",
  "name": "Repeated font probing",
  "category": "Fingerprinting",
  "description": "A page used font-probing signals at least ten times.",
  "severity": "medium",
  "match": {
    "indicatorId": "font-probing",
    "minCount": 10
  }
}

signals accepts up to 20 matchers. hosts accepts domain suffixes such as metrics.example. Set mode to any or all. Severity may be low, medium, or high.

Custom indicators are matching rules only. They never execute code, read page contents, or add new browser instrumentation.

Veilance JSON tracker format

Veilance tracker files store domains and filters as JSON arrays. Veilance supports host-anchored network filters such as ||tracker.example^$3p. $3p, first-party forms, common resource types, and domain= constraints are honored. Path, cosmetic, regular-expression, redirect, and exception filters are skipped with a visible warning because Veilance history intentionally does not retain URL paths.

{
  "format": "veilance-json",
  "name": "Platform161",
  "category": "advertising",
  "website_url": "https://platform161.com/",
  "organization": "platform161",
  "domains": [
    "creative-serving.com",
    "p161.net"
  ],
  "filters": [
    "||ads.creative-serving.com^$3p",
    "||p161.net^$3p"
  ]
}

The format field is recommended but optional when domains or filters is present. The rule name is required. organization becomes the default rule id, and description, severity, and defaultEnabled remain optional. Keep the built-in network-requests indicator enabled so tracker rules have request hosts to evaluate.
